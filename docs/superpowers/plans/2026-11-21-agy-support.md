# Antigravity CLI (agy) Support Implementation Plan

> **For agentic workers:** Use `executing-plans` to implement this plan in the current session, task by task. Steps use checkbox (`- [ ]`) syntax. Tasks 1 to 9 and the first commit of Task 10 are already committed; start at Task 11. The second commit of Task 10 (versions and docs) comes after Task 11 Step 2, so that the docs state what the real agy was seen to do.

**Goal:** auto-learn works in Antigravity CLI: after an attended turn with enough tool calls, a background review saves a skill that agy offers from the next conversation on. The result is proven on the real `agy`, pushed to `origin/main`, and installed into the owner's agy from the GitHub URL.

**Architecture:** A native agy plugin at the repository root (`.antigravity-plugin/plugin.json`, `hooks.json`, `mcp_config.json`, `agents/`) beside the other hosts' files. SessionStart injects guidance and the learned-skill list. Stop reads the turn from the transcript, decides eligibility and starts the existing detached worker, which runs one fresh headless `agy -p` review, confined to `manage_skill`, in a private conversation store that is emptied after each run.

**Tech stack:** ECMAScript modules, Node 18+, zero dependencies, `node:test`; the real `agy` 1.5.14 for verification.

**Spec:** `docs/superpowers/specs/2026-11-21-agy-support-design.md` (read it first; this plan only records the decisions it leaves to the implementer).

## Global Constraints

- Node 18+, no runtime dependencies; the other five hosts behave exactly as before (their tests stay green and untouched except where a shared signature grows).
- One host id, `agy`, everywhere: `--host=agy`, `job.host`, `prompts/agy/`, `parseHost`.
- `hooks.json` registers only SessionStart (timeout 10) and Stop (timeout 30), each `node ./scripts/hook.mjs <event> --host=agy`. Never register PreToolUse (a hook that prints `{}` there is a deny). No root `plugin.json` (Copilot CLI would prefer it).
- Review command: `agy -p "" --input-format stream-json --output-format stream-json --agent auto-learn-review --print-timeout 240s --settings '{"toolPermission":"always-proceed"}' --disable-slash-commands --app_data_dir=auto-learn-review`; prompt on stdin as one NDJSON line, then stdin closed; cwd `<data dir>/review-workspace`; SIGTERM at 300 s, SIGKILL 5 s later, to the whole process group (`detached: true`, `process.kill(-pid, ...)`); stderr in a 64 KiB sink; stdout lines capped at 8 MiB.
- Excerpt limits: user 4,000, reply 2,000, call arguments 600, result 1,200, total 60,000 characters (`EXCERPT_LIMITS`). Prompt first line `[auto-learn review]`.
- Child environment drops exactly `ANTIGRAVITY_CONVERSATION_ID`, `PLUGIN_ROOT`, `PLUGIN_DATA` (plus `forkEnvironment`'s own list) and adds `AUTO_LEARN_CAPTURE=1`, `AUTO_LEARN_PROJECT_DIR`. The environment, the prompt and the excerpt never reach a log, a job file or an error message.
- Data directory for agy: `$PLUGIN_DATA`, else `~/.gemini/antigravity-cli/plugin_data/auto-learn`. Skills: `~/.gemini/config/skills`. Review store: `~/.gemini/auto-learn-review`.
- Version 0.5.0 in `package.json` and the Claude, Codex, Copilot and agy manifests. Commits: imperative subject up to 72 characters, body wrapped at 72 saying problem, why, risk; refactors apart from behavior; no attribution lines; no `--no-verify`.
- Every new test is shown to fail with its bug put back (saboteur), and a failing test is seen red before its code exists.

## Review Focus

- The review's conversation id comes from agy's stream, which carries attacker-influenced text: a crafted id must never reach a path (Task 6 test: `../`, absolute and non-UUID ids delete nothing).
- Two sessions end turns together: two workers, two reviews in one store. Each deletes only its own id and the sweep spares anything under an hour old (Task 6 test).
- The model calls a tool other than `manage_skill`, or `manage_skill` on another server: the run stops and nothing but a name is logged (Tasks 7 and 8 tests: stream and runner).
- An excerpt containing the closing marker, `</USER_REQUEST>` or request-like text cannot end its block: the markers carry a per-run random nonce absent from the excerpt (Task 8 test).
- `agy` is missing, prints non-JSON, never prints a result, hangs, ignores SIGTERM, or leaves a grandchild: each ends in a recorded outcome within the limits, with no process left (Task 8 tests with the stand-in).
- The project folder is deleted, `HOME` is unwritable or the disk is full between Stop and the worker: the record says `skipped` or `error`, the hook and agy are unaffected (Tasks 8 and 9 tests).

## Task 7: read the review's stream (`scripts/lib/agy-stream.mjs`)

**Files:** create `scripts/lib/agy-stream.mjs`, `test/agy-stream.test.mjs`, `test/fixtures/agy-review-stream.ndjson` and `test/fixtures/agy-review-denied.ndjson` (the real L6 and L7 streams, prompt text replaced); add the `agyStream` event builders to `test/helpers.mjs`.

**Interfaces:**
- Produces: `createStreamAnalyzer(): { accept(event: object): { stop: string } | undefined, finish(): StreamSummary }` where `StreamSummary` is `{ conversationId?: string, status?: string, finishedReason?: string, error?: string, deniedActions: number, skillCalls: number, saves: Array<{action, name}>, otherToolCalls: number, otherTools: string[], stoppedTool?: string, inputTokens: number, cacheReadTokens: number, outputTokens: number }`; a value that is not known is left out.
  - `init` and every step event carry `conversation_id`: the `init` one wins, else the first seen. The `result` event's `result` is an object with `status`, `finished_reason`, `error` (clipped to 500 characters) and `denied_actions` (a list; its length is `deniedActions`). Its own `usage` is not read.
  - Tokens are summed over the `agent_response` steps that reached `DONE`, one `usage` per `step_index`. `inputTokens` adds `cache_read_tokens`, which agy leaves out of `input_tokens`; `outputTokens` adds `thinking_tokens`.
  - A tool step (`step_type: "tool"`) is judged on its first event by `tool_name`. `call_mcp_tool` with `ToolName` `manage_skill` on a server named `auto-learn` or ending `_auto-learn` (agy names a plugin's server `<plugin folder>_<server key>`) is the review's own and counts in `skillCalls`. `list_resources`, `read_resource` and `manage_task`, which agy gives every agent, count in `otherToolCalls` and are ignored. Anything else makes `accept` return `{ stop }` (for a foreign MCP call `"call_mcp_tool:<server>/<tool>"`), clipped to 256 characters, sets `stoppedTool`, and ends the analysis: later events are ignored.
  - A `manage_skill` call is a save only when its step reaches `DONE` with a non-empty `tool_info.output` and no `tool_info.error`; the saved value is `requestedSave(arguments)` (`capture.mjs`), so a refused or unknown action is not one. A permission denial under strict mode also reaches `DONE`, with no output; the result's `denied_actions` shows it.

## Task 8: the review runner (`scripts/lib/agy.mjs`)

**Files:** create `scripts/lib/agy.mjs`, `test/fake-agy.mjs`, `test/agy-capture.test.mjs`.

**Interfaces:**
- Consumes: `scanTurn`/`renderTurn`/`EXCERPT_LIMITS` (Task 2), `captureNudge`/`learnedSkillLines` (Task 3), `reviewStoreDir`/`removeConversation`/`sweepStore` (Task 6), `createStreamAnalyzer` (Task 7), and from `capture.mjs` `forkEnvironment`, `boundedSink`, `isDirectory`, `isFile`, `skillChanges`; `learnedSkills` and `skillsDir(env, "agy")`; `lineSplitter` (`jsonl.mjs`); `isValidSessionId` (`state.mjs`).
- Produces: `agyReviewEnvironment(env: object, projectDir: string): object`.
- Produces: `runAgyReview({ prompt, cwd, env, signal, timeoutMs?, killGraceMs? }): Promise<{ outcome: "ok" | "error" | "timeout" | "aborted" | "stopped", reason?, error?, summary: StreamSummary }>`: spawns `agy` with the Global Constraints command, writes the NDJSON prompt line `{"event":"user","message":{"content":[{"type":"text","text":<prompt>}]}}`, parses stdout lines through the analyzer, kills the process group on timeout, abort or `stop`. `ok` needs a `result` with `status` `SUCCESS` and no denied actions; `denied_actions` is an `error` ("agy denied N actions"); a review that was stopped (timeout, abort, foreign tool) is reported as stopped even if it printed an error result on the way out, but a `SUCCESS` result printed before the stop stands; any other result is an `error` with agy's own text, else "agy ended with the status X"; no `result` is an `error` carrying the exit status and the last 500 characters of stderr; a missing binary is "the agy CLI was not found on PATH". After the child closes, a stopped review's process group gets a SIGKILL too, so a child that ignored SIGTERM does not outlive it.
- Produces: `captureAgyTurn(job, { env?, signal? }): Promise<Record>` with `job = { host: "agy", sessionId, transcriptPath, start, end, toolCalls, projectDir }`. Returns `{ outcome: "skipped", reason }` for a malformed job, a missing transcript or a missing project folder; otherwise the runner's outcome plus `created`, `updated`, `deleted` (from `skillChanges`), `skillCalls`, `otherToolCalls`, `otherTools`, `deniedActions`, `stoppedTool`, `inputTokens`, `cacheReadTokens`, `outputTokens`, `cleanupError` when cleanup failed, and `durationMs`. Order: sweep the store, render the excerpt for [start, end), list the saved skills (`"none yet"` when empty), build the prompt (`[auto-learn review]`, a blank line, `BEGIN <nonce>`, excerpt, `END <nonce>`, a blank line, `captureNudge("manage_skill", "agy", { skills })`; the nonce is 16 random hex digits), run, then `removeConversation` with the id from the stream whatever the outcome.
- `test/fake-agy.mjs` is a node script behind a `#!/bin/sh` shim on `PATH`; modes `ok` (a junk line, init, a `manage_skill` create step that reaches DONE with output, a SUCCESS result; it writes no skill file, since skill writing belongs to the MCP server's own tests), `refused` (denied_actions, `$FAKE_AGY_DENIED` of them), `failed` (the result in `$FAKE_AGY_RESULT`, exit 3), `exit` (no result, exit 3, `$FAKE_AGY_STDERR`, before reading the prompt), `hang` (init, then nothing until killed), `stubborn` (ignores SIGTERM and has a child that ignores it too and records its pid), `polite` (like `hang` with such a child, but prints an ERROR result and exits on SIGTERM), `rogue` (a `run_command` step, then it would write a marker file after 8 seconds), `badid` (a conversation id that is a path outside the store). It creates `<HOME>/.gemini/<--app_data_dir value>/{brain,conversations,presence}/<id>*` like the real one, and records args, cwd, selected env and stdin to `$FAKE_AGY_RECORD`.
